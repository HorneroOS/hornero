# Release checklist: v0.2.0-preview2

Release definition: `v0.2.0-preview2.yaml`. Check each box before
tagging. Unchecked boxes block the release.

## Composition

- [ ] Manifest `hornero-0.2.0-preview2` pins the frozen `shell` and
  `config` release-candidate SHAs with commit subjects recorded.
- [ ] `manifests/v0.1.0-draft.yaml` is byte-identical to tag
  `v0.1.0-draft` (historical, never rewritten).
- [ ] `manifests/candidate` names `v0.2.0-preview2.yaml`.
- [ ] `installer` and `iso` are present as `future` slots only, with
  no `sha` or `ref`.
- [ ] Profiles `base`, `desktop`, and `developer` reference the
  Preview 2 manifest and ship only `pinned` or `local` components.
- [ ] Profile extension chain (`developer` -> `desktop` -> `base`)
  resolves with no cycles.

## Validation

- [ ] `python3 scripts/check-manifests.py` exits 0.
- [ ] `python3 scripts/check-pins.py` exits 0 (candidate freshness).
- [ ] `python3 -m pytest tests/ -q` passes.
- [ ] `markdownlint` is clean on all new or touched Markdown files.
- [ ] `./scripts/compose.sh --yes` is green locally and as the `compose`
  job in `composition-ci`.
- [ ] `tests/vm/smoke.sh` is green on KVM.

## Hygiene

- [ ] Personal-data and secrets rescan shows no findings
  (names, emails, hosts, SSIDs, tokens, keys).
- [ ] No git submodules added (`git submodule status` is empty).
- [ ] Commits are small, English-only, on the release branch.
  `main` is never pushed directly.

## Tag and build order

- [ ] Branch is pushed; CI (`composition-ci`) is green.
- [ ] Tag `v0.2.0-preview2` created per `docs/RELEASE_PROCESS.md`
  from `main` after merge; tag history of `v0.1.0-draft` untouched.
- [ ] Build order followed: `horneroctl`, then `config`, then
  `shell`; `installer` and `iso` slots recorded as skipped.
